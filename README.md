# CRM Система управления задачами (MVP)

Простая и эффективная система управления проектами и задачами, написанная на нативном PHP без использования фреймворков и JavaScript.

## Требования к серверу

*   PHP 5.3 - 8.x
*   MySQL 5.3+ (или совместимая)
*   Расширения PHP: `pdo`, `pdo_mysql`

## Установка

1.  **Копирование файлов:**
    Загрузите все файлы из репозитория в корневую директорию вашего веб-сервера.

2.  **Настройка базы данных:**
    *   Создайте базу данных в MySQL (например, `crm_db`).
    *   Импортируйте структуру таблиц из файла `schema.sql`.
    *   Откройте файл `db.php` и укажите настройки подключения:
        ```php
        $host = 'localhost';
        $dbname = 'crm_db';
        $user = 'ваш_пользователь';
        $pass = 'ваш_пароль';
        ```
    *   **Миграция (для обновлений):** Если вы обновляете систему, запустите `php migrate.php` (или выполните SQL-команды из него вручную), чтобы обновить структуру БД.

3.  **Права доступа:**
    Убедитесь, что папка `uploads/` доступна для записи веб-сервером.

## Первый вход

По умолчанию в системе создан один администратор:

*   **Логин:** `admin`
*   **Пароль:** `12345`

*Рекомендуется сменить пароль или создать нового администратора сразу после входа.*

# Документация для разработчиков и AI (Контекст проекта)

Этот раздел предназначен для понимания архитектуры системы, логики работы файлов и структуры базы данных. Используйте его как контекст для доработок.

## 1. Архитектурные принципы
*   **Native PHP:** Код написан на чистом PHP (совместим с версиями 5.3 - 8.x). Использование фреймворков (Laravel, Symfony) запрещено.
*   **One URL = One File:** Отсутствует единая точка входа (Router). Каждый URL соответствует конкретному PHP-файлу (например, `/tasks_list.php`).
*   **No Heavy JS:** Интерактивность реализована через нативные HTML-формы. JavaScript используется минимально (только если без него невозможно, например, подтверждение удаления). Использование тяжелых библиотек (React, Vue, jQuery) запрещено.
*   **PDO:** Взаимодействие с БД только через PDO для безопасности (Prepared Statements).
*   **CSS:** Используется собственный `style.css` без препроцессоров. Адаптивность реализована через `@media`.

## 2. Структура базы данных

### Таблицы
1.  **`users`**
    *   Пользователи системы.
    *   Поля: `login`, `password` (hash), `role` ('admin' | 'employee'), `first_name`, `last_name`, `email`, `phone`, `position`.
2.  **`projects`**
    *   Проекты, объединяющие задачи.
    *   Поля: `name`.
3.  **`tasks`**
    *   Основная сущность.
    *   Поля: `project_id` (FK), `creator_id`, `assignee_id`, `status` ('waiting', 'in_progress', 'review', 'done', 'archive'), `priority`, `deadline`, `created_at`, `updated_at`, `started_at`.
4.  **`comments`**
    *   Комментарии к задачам.
    *   Поля: `task_id`, `user_id`, `text`, `created_at`.
5.  **`attachments`** (Новая в v2.0)
    *   Хранит пути к файлам. Реализует полиморфную связь (одна таблица для задач и комментариев).
    *   Поля: `entity_type` ('task' | 'comment'), `entity_id`, `file_path`, `created_at`.
6.  **`task_views`** (Новая в v2.0)
    *   Отслеживание просмотров задач пользователями для уведомлений ("оранжевый маркер").
    *   Поля: `user_id`, `task_id`, `last_viewed_at`.

### Логика связей и удаления (Cascade)
*   При удалении **Проекта** -> Удаляются все его **Задачи**.
*   При удалении **Задачи** -> Удаляются все её **Комментарии**, записи в `attachments` и `task_views`.
*   **Важно:** Физическое удаление файлов с диска должно происходить **до** удаления записи из БД (реализовано в `project_delete.php` и `task_delete.php`), так как после каскадного удаления в БД пути к файлам будут потеряны.

## 3. Описание файлов и их ответственности

### Ядро и Конфигурация
*   **`db.php`**: Подключение к БД, настройки окружения (`TEST_ENV`). Содержит глобальные хелперы:
    *   `upload_files($filesArray)`: Загрузка нескольких файлов.
    *   `delete_file_from_disk($path)`: Безопасное удаление файла.
*   **`auth.php`**: Управление сессиями. Функции `require_login()`, `require_admin()`, `current_user_role()`.
*   **`migrate.php`**: Скрипт для обновления структуры БД (DDL).

### Аутентификация
*   **`login.php`**: Форма входа. Перенаправляет на `tasks_list.php`.
*   **`logout.php`**: Завершение сессии.

### Проекты
*   **`projects_list.php`**: Список проектов. Поиск, сортировка. Для "Employee" скрыт в меню, но доступен прямой ссылкой (read-only).
*   **`project_view.php`**: Детали проекта + список задач проекта.
*   **`project_delete.php`**: Удаление проекта + рекурсивное удаление файлов всех задач проекта.
*   **`project_clone.php`**: Логика клонирования проекта (сброс статусов и исполнителей).

### Задачи
*   **`tasks_list.php`**: Главная страница. Таблица задач с фильтрами, поиском, пагинацией (опционально) и маркерами непрочитанных обновлений.
*   **`task_create.php`**: Форма создания (только Admin). Поддержка мультизагрузки файлов.
*   **`task_view.php`**: Просмотр задачи.
    *   Логика смены статусов (Employee: Start->Complete, Admin: Done/Archive).
    *   Добавление комментариев с файлами.
    *   Фиксация просмотра в `task_views`.
*   **`task_edit.php`**: Редактирование метаданных задачи (Admin).
*   **`task_delete.php`**: Удаление задачи + удаление файлов задачи и файлов её комментариев.

### Пользователи
*   **`users.php`**: Список сотрудников (Только Admin).
*   **`user_view.php`**: Просмотр профиля.
*   **`user_edit.php`**: Редактирование профиля.
    *   Admin: меняет всё (роль, логин, пароль).
    *   Employee: меняет только свои контакты и пароль.
*   **`user_delete.php`**: Удаление сотрудника с очисткой связанных данных (Admin).

## 4. UI/UX Принципы
*   **Мобильная адаптация:** Использовать Media Queries в `style.css`. На экранах < 768px меню превращается в стек ссылок, таблицы становятся прокручиваемыми (`.table-responsive`).
*   **Роли:**
    *   Элементы интерфейса для Admin (кнопки "Удалить", "Редактировать") должны быть обернуты в проверку `if ($role === 'admin')`.
    *   Ссылки на "Проекты" скрываются для "Employee".
